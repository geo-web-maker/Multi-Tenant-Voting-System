# Backup monitoring / mirror / restore-test deviations

1. **Seven sub-tabs instead of one long page (intentional, as specified in §8.0).** The Site Usage tab is a single long page; the Backups control room contains seven distinct areas and would require excessive scrolling on phones. The Backups tab therefore uses the existing Voters-style `role="tablist"` pattern for Overview, Connections, Backblaze, Second DB, Staging (restore test), Migration and Settings. Within each sub-tab the existing Site Usage / Performance card, loading, polling, chart and alert conventions are retained.
2. **Environment-only keep-data flag is displayed read-only.** `RESTORE_TEST_KEEP_DATA` is an environment setting, not a setting stored in `platform_settings`; the tab reports its configured state without offering a misleading UI toggle. Change it in the deployment environment only.
3. **Live Atlas/B2/Render cutover and browser visual checks are intentionally not performed in this build environment.** These actions require the operator's actual connection strings, network allow-list, retained backup credentials and a live maintenance window. No live data was migrated or scratch database flushed during implementation. The acceptance/human checks are listed in `progress/BK-9.md` through `progress/BK-11.md` and the runbook.
